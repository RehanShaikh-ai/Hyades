# v0.4.1 Infrastructure Architecture

**Release:** v0.4.1 — Usability, Sources & Persistent Assistant  
**Workstream:** C — Infrastructure, Database & Integration  
**Contract:** `docs/contracts/CONTRACT_v0.4.1.md`  

---

## 1. Overview

v0.4.1 introduces the Source System (first-class file ingestion pipeline for PDF, Markdown, and plain text) and the Persistent AI Assistant (conversations, messages, and citation tracking).

From an infrastructure perspective:
1. **No new runtime services**: All core runtime workloads continue running on existing services (PostgreSQL 16, Qdrant 1.9.1, Redis 7, ARQ Worker).
2. **Playwright E2E Testing Service**: Added to `docker-compose.yml` under the `e2e` profile (`mcr.microsoft.com/playwright:v1.44.0-jammy`) for automated browser integration in CI without burdening standard runtime environments.
3. **Database Unification**:
   - `note_chunks` is deprecated and migrated into `content_chunks`, unifying note and source chunking.
   - `sources` table receives non-breaking lifecycle extensions.
   - `conversations`, `messages`, `message_citations`, and `source_note_links` are created.
4. **Environment Variables**: Documented in `.env.example` per §15 for conversation history limits, file upload limits, and processing timeouts.

## 3. Database Schema & Migration Specification (§6)

### Schema-Handoff Gate Protocol (§0.1)

Per CONTRACT §0.1:
- Workstream B must first finalize models (`ContentChunk`, `Conversation`, `Message`, `MessageCitation`, `Source` extensions) and update `backend/app/models/__init__.py`.
- Workstream B opens `schema-handoff/v0.4.1` containing only models and `__init__.py`.
- Only after `schema-handoff/v0.4.1` is merged to `main` does Workstream C build and test the Alembic migration.

### Planned Revision (`0007_sources_content_chunks_and_conversations.py`)

1. **`sources` table extensions**:
   - `processing_stage` (String 50, default `upload`)
   - `processing_status` (String 20, default `PENDING`)
   - `file_size_bytes` (BigInteger, nullable)
   - `page_count` (Integer, nullable)
   - `chunk_count` (Integer, nullable)
   - `error_stage` (String 50, nullable)
2. **`content_chunks` table (Unification)**:
   - Replaces `note_chunks`.
   - Fields: `id` (UUID PK), `workspace_id` (UUID FK), `note_id` (UUID FK, nullable), `version_id` (UUID FK, nullable), `source_id` (UUID FK, nullable), `chunk_index` (Integer), `content` (Text), `content_hash` (String 64), `token_count` (Integer), `embedding_model` (String 100), `embedding_dimension` (Integer), `created_at` (DateTime UTC).
   - Data migration: copy all existing `note_chunks` rows into `content_chunks` (mapping `source_id=NULL`).
   - Foreign key migration: re-point `entity_chunks.chunk_id` to `content_chunks.id`.
   - Drop `note_chunks` table.
3. **`conversations` table**:
   - `id` (UUID PK), `workspace_id` (UUID FK), `title` (String 200), `created_at`, `updated_at`.
4. **`messages` table**:
   - `id` (UUID PK), `conversation_id` (UUID FK), `workspace_id` (UUID FK), `role` (String 20: `user` or `assistant`), `content` (Text), `provider` (String 50, nullable), `model` (String 100, nullable), `latency_ms` (Integer, nullable), `created_at`.
5. **`message_citations` table**:
   - `id` (UUID PK), `message_id` (UUID FK), `chunk_id` (UUID FK), `note_id` (UUID FK, nullable), `source_id` (UUID FK, nullable), `workspace_id` (UUID FK), `similarity_score` (Float, 0.0-1.0), `rank` (Integer).
6. **`source_note_links` table (Association)**:
   - Composite PK: `(source_id, note_id)` with CASCADE FKs.

### Required Indexes (§6.7)

- `idx_source_extensions` on `sources(workspace_id, processing_status)`
- `idx_content_chunks_note` on `content_chunks(note_id)`
- `idx_content_chunks_source` on `content_chunks(source_id)`
- `idx_content_chunks_workspace` on `content_chunks(workspace_id)`
- `idx_conversations_workspace` on `conversations(workspace_id, updated_at DESC)`
- `idx_messages_conversation` on `messages(conversation_id, created_at ASC)`
- `idx_message_citations_message` on `message_citations(message_id)`
- `idx_source_note_links_source` on `source_note_links(source_id)`
- `idx_source_note_links_note` on `source_note_links(note_id)`

## 4. Environment Variables (§15)

Documented in `.env.example`:
- `CONVERSATION_HISTORY_LIMIT=10`: Maximum conversation history messages injected into LLM prompt.
- `SOURCE_MAX_FILE_SIZE_MB=25`: Maximum individual upload file size in megabytes.
- `SOURCE_PROCESSING_TIMEOUT_SECONDS=120`: Processing timeout for background extraction jobs.

## 5. CI / CD & Playwright Integration (§16)

The GitHub Actions CI pipeline (`.github/workflows/ci.yml`) enforces:
1. **Backend Lint & Tests**: Unit tests with pytest, ruff formatting and linting.
2. **Alembic Migrations Check**: Linear history and script directory validation via `verify_migrations.py`.
3. **Docker Compose Validation**: Validates syntax including the `playwright` service under `--profile e2e`.
4. **Integration Tests**: Testcontainers PostgreSQL test suite verifying migration upgrade, downgrade reversibility, and constraint integrity.
5. **Frontend Lint, Test & Build**: Vitest test suite and production build verification.
6. **Playwright E2E Tests**: Dedicated CI job running browser end-to-end tests against the application.
