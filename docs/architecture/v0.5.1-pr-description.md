## 🎯 Key Capabilities & Deliverables

### 1. Database Persistence & Models (§4.1, §4.2)
- **`ActionExecution`**: Tracks full lifecycle (`pending`, `running`, `proposed`, `awaiting_confirmation`, `succeeded`, `failed`, `cancelling`, `cancelled`), `idempotency_key`, duration, payloads, and error states.
- **`ActionProposal`**: Stores proposal payloads and **SHA-256 token hashes (`confirmation_token_hash`)**. Raw tokens are never persisted to disk or DB. 15-minute expiration window enforced.
- **`ActionChangeSet`**: Captures `before_state` and `after_state` snapshots for safe rollback and undo tracking (`not_undone`, `undone`, `cannot_undo`).
- *Note:* Alembic migrations remain untouched for Ali (Infrastructure owner); schema specification handoff is fully documented in `docs/architecture/v0.5.1-schema-handoff.md`.

### 2. Frozen Action Registry & Schemas (§5.2, §7, §15.1)
- Frozen catalogue containing exactly **37 canonical actions**:
  - **Read (12):** `knowledge.search_all`, `notes.get`, `notes.search`, `sources.get`, `sources.search`, `sources.get_processing_status`, `entities.get`, `entities.search`, `graph.get_neighbors`, `graph.find_path`, `collections.get`, `threads.get`.
  - **Understand (11):** `notes.summarize`, `sources.summarize`, `collections.summarize`, `threads.summarize`, `entities.summarize`, `notes.compare`, `sources.compare`, `knowledge.answer`, `knowledge.generate_brief`, `notes.extract_concepts`, `notes.suggest_tags`.
  - **Review (8):** `inbox.list`, `inbox.accept`, `inbox.reject`, `sources.retry_processing`, `knowledge.audit_processing`, `graph.find_isolated_nodes`, `graph.suggest_relationships`, `notes.find_related`.
  - **Controlled Writes (6):** `notes.create`, `notes.update`, `notes.link`, `collections.add_item`, `graph.add_relationship`, `notes.delete`.

### 3. Execution Service & Two-Phase Writes (§6.1, §6.2, §6.4, §6.5, §6.6)
- **Two-phase mutation workflow:**
  - `mode="propose"`: Validates inputs, creates preview, captures before-state, issues single-use URL-safe 32-byte token.
  - `mode="commit"`: Verifies SHA-256 hash match, validates token non-expiry, commits atomically, records change set.
  - Rejection / Reuse: Already-committed or rejected tokens return `409 Conflict`.
- **Reversible undo engine (`execute_undo`):**
  - Fully supports undoing all 6 write mutations, cleanly restoring original state.
- **Destructive delete protections:** Note title validation and snapshot recovery before deletion.

### 4. API Routes & Concurrency Controls (§5, §9, §11.2, §11.3)
- `GET /api/v1/actions`: Canonical catalogue.
- `POST /api/v1/actions/{action_id}/execute`: Unified execution endpoint (`read`, `propose`, `commit`).
- `GET /api/v1/actions/executions/{id}`: Status & result envelope.
- `POST /api/v1/actions/executions/{id}/cancel`: Active execution cancellation.
- `GET /api/v1/actions/executions`: Paginated execution listing.
- `POST /api/v1/actions/proposals/{id}/reject`: Proposal rejection.
- `POST /api/v1/actions/change-sets/{id}/undo`: Revert mutation.
- **Concurrency & Idempotency:** Max 2 concurrent running executions per workspace (`429 Too Many Requests` on overflow). Duplicate `idempotency_key` deduplication.
