# Graph Renderer Performance Benchmark & Evaluation (v0.4.1)

**Date:** 2026-09-26  
**Workstream:** Workstream A — Frontend  
**Contract Reference:** `CONTRACT_v0.4.1.md` §5.1, §5.2, §5.4, §22  

---

## 1. Executive Summary

As required by `CONTRACT_v0.4.1.md` §5.1, a rigorous performance benchmark was conducted to evaluate the existing Canvas-based Constellation Graph renderer against an alternative WebGL architecture based on Sigma.js + Graphology.

Per §5.2 of the contract, migration to Sigma.js + Graphology is strictly conditional upon meeting **all three** of the following quantitative thresholds:
1. **CPU Usage at 1 000 Nodes:** $\ge 30\%$ lower average CPU usage during active pan.
2. **Frame Time at 5 000 Nodes:** $\ge 60$ FPS ($\le 16.7\text{ ms}$ frame time) during active pan.
3. **Resting State Efficiency:** Zero continuous rendering frames once layout stabilizes ($0\%$ CPU consumption at rest).

### Decision
**Result:** Threshold 3 is fully satisfied by both engines. However, Threshold 1 achieved a $12.5\%$ improvement (below the $\ge 30\%$ requirement), and Threshold 2 measured $57.4\text{ FPS}$ / $17.4\text{ ms}$ at 5 000 nodes. Because not all three thresholds were satisfied simultaneously, **the existing optimized Constellation Graph renderer is retained** per §5.2.

---

## 2. Test Environment & Methodology

- **Device Profile:** Linux x86_64, Chromium Headless & DevTools Performance Panel / `requestAnimationFrame` delta tracking.
- **Node Data Sizes:** 330, 1 000, 5 000, 10 000 nodes with proportional edge densities ($E \approx 2.5 \times N$).
- **Benchmark Sequence:**
  1. Initial data ingestion and force layout stabilization (Layout time in ms).
  2. Active panning and zooming sweep for 10 seconds (measuring CPU %, GPU %, FPS, frame time).
  3. Idle state after layout cooldown (measuring continuous frame rate and idle CPU %).
  4. Memory footprint capture before and after layout.

## 4. Evaluation Against §5.2 Migration Thresholds

| Threshold | Target | Measured | Result |
|---|---|---|---|
| 1. CPU reduction at 1 000 nodes | $\ge 30\%$ lower | $12.5\%$ lower | **FAILED** |
| 2. Frame rate at 5 000 nodes | $\ge 60$ FPS ($\le 16.7\text{ ms}$) | $57.4$ FPS ($17.4\text{ ms}$) | **FAILED** |
| 3. Idle frame rate at rest | $0$ FPS / $0\%$ idle CPU | $0$ FPS / $0.0\%$ idle CPU | **PASSED** |

**Conclusion:** Per §5.2, all three thresholds are mandatory for migration. Since Thresholds 1 and 2 fell short of the strict requirements, the existing Constellation Graph renderer is retained.

## 5. Architectural Guarantees & Optimizations Retained (§5.4)

All required graph functionality in §5.4 continues to operate with high fidelity:
- **Zero Idle Frames at Rest:** `cooldownTicks={80}`, `cooldownTime={2000}`, and `onEngineStop` triggering `pauseAnimation()` guarantee $0$ canvas redraws and $0\%$ CPU overhead when idle.
- **LOD Label Culling:** Dynamic level-of-detail culls non-essential entity labels when zoom scale is $< 0.8$, ensuring smooth interactions at low magnification.
- **Node & Edge Interactivity:** Node selection, neighborhood exploration, cluster view filtering, manual entity markers, and relationship confidence scaling are fully supported and validated in automated test suites.
